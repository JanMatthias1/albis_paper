### Computational benchmarking

We benchmarked ALBIS, scCube and SPIDER at eight sizes from 10,000 to 5,000,000 cells (556 genes, one CPU thread, three simulation seeds per method and size) on shared cluster nodes of a single hardware type (Intel Xeon Platinum 8558U). Each method ran through its native API, and each size ran as a separate program. Tissue extent (and, for ALBIS, sphere radius) was scaled from the 600,000-cell configuration by $(n/600{,}000)^{1/3}$, keeping cell density constant. Simulation time was the wall-clock time from building the three-dimensional tissue to cell-level data in ten sections along $z$. Setup-inclusive time added Splatter reference generation and input loading (scCube, SPIDER) and VAE training (scCube; 200 epochs on the 10,000-cell reference, retrained in every run, no checkpoints saved); ALBIS required no setup. SPIDER did not complete at 5,000,000 cells: sectioning its expression exceeded the 32-bit index limit of scipy's sparse matrices, independent of available memory.

Memory was each program's peak RAM use. For scCube, generation memory excludes VAE training and was sampled every 100 ms. Setup-inclusive memory is the most RAM needed at any point in the full workflow: the larger of the Splatter reference's and the method's peak, as the two run one after the other. We report the mean over seeds and show each seed individually.
