### Computational benchmarking

We benchmarked ALBIS, scCube and SPIDER at eight output sizes (10,000–5,000,000 cells), using 556 genes, one computational CPU thread and three simulation seeds (2025, 101, 202) per method and size. Methods were executed through their native APIs, preserving their returned representations: explicit molecules for ALBIS and cell-level expression and metadata for scCube and SPIDER. Simulation settings were scaled from the 600,000-cell configuration by (n / 600,000)^(1/3) in tissue extent. Wall-clock simulation time covered each method's native calls from generating the 3D tissue to cell-level data cut into ten sections along z (ALBIS sectioning without batch effect or slice offsets; SPIDER's slice_anndata_by_z, applied to the expression object SPIDER returned; scCube's own z-splitting), without bin- or spot-level capture, and excluded reference construction and VAE training; setup-inclusive time additionally included Splatter reference generation, input loading and, for scCube, VAE training. Every method ran each size in a separate process; for scCube, each run trained its own VAE on the 10,000-cell Splatter reference (fixed 200 epochs) before generating, and that run's training time was included in its setup-inclusive time. No model checkpoints were saved. Timing excluded imports/startup, validation, aggregation and output export. We report the mean over the three seeds, with individual seeds shown. SPIDER did not complete at 5,000,000 cells: sectioning its cell-level expression with slice_anndata_by_z exceeded the 32-bit index limit of scipy's sparse matrices (ValueError in scipy's row indexing, with the process at about 6.5 GiB, far below available memory), so no SPIDER value is reported at that size.

Each method ran each size as a separate program, and we report memory as each program's peak RAM use. For generation memory, this is the peak of the whole run for ALBIS and SPIDER. For scCube, which trains a VAE before generating in the same run, we report the peak during generation only, measured every 100 ms. Setup-inclusive memory also counts the setup steps. ALBIS has no setup, so its two values are the same. For SPIDER and scCube, it is the higher of two peaks: that of the Splatter reference run and that of the method's own run (for scCube, including VAE training). We report the mean over seeds and show each seed individually.
