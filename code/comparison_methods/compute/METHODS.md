### Computational benchmarking

We benchmarked ALBIS, scCube and SPIDER at eight output sizes (10,000–5,000,000 cells), using 556 genes, one computational CPU thread and three simulation seeds (2025, 101, 202) per method and size. Methods were executed through their native APIs, preserving their returned representations: explicit molecules for ALBIS, expression and metadata for scCube, and reference-backed expression views for SPIDER. Simulation settings were scaled from the 600,000-cell configuration by (n / 600,000)^(1/3) in tissue extent. Wall-clock simulation time covered each method's native calls from generating the 3D tissue to cell-level data cut into ten sections along z (ALBIS sectioning without batch effect or slice offsets; SPIDER's slice_anndata_by_z; scCube's own z-splitting), without bin- or spot-level capture, and excluded reference construction and VAE training; setup-inclusive time additionally included Splatter reference generation, input loading and, for scCube, VAE training. Every method ran each size in a separate process; for scCube, each run trained its own VAE on the 10,000-cell Splatter reference (fixed 200 epochs) before generating, and that run's training time was included in its setup-inclusive time. No model checkpoints were saved. Timing excluded imports/startup, validation, aggregation and output export. We report the mean over the three seeds, with individual seeds shown.

Memory was each run's peak resident set size, which for scCube includes VAE training; scCube's generation-only memory was the peak of resident memory sampled every 100 ms during generation. For SPIDER and scCube, setup-inclusive memory was the larger of this peak and the peak of the separate Splatter reference process, which runs beforehand.
