### Computational benchmarking

We benchmarked ALBIS, scCube and SPIDER at eight output sizes (10,000–5,000,000 cells), using 556 genes, one computational CPU thread and three simulation seeds (2025, 101, 202) per method and size. Methods were executed through their native APIs, preserving their returned representations: explicit molecules for ALBIS, expression and metadata for scCube, and reference-backed expression views for SPIDER. Simulation settings were scaled from the 600,000-cell configuration by (n / 600,000)^(1/3) in tissue extent. Wall-clock simulation time covered each method's native calls from generating the 3D tissue to cell-level data cut into ten sections along z (ALBIS sectioning without batch effect or slice offsets; SPIDER's slice_anndata_by_z; scCube's own z-splitting), without bin- or spot-level capture, and excluded reference construction and VAE training; setup-inclusive time additionally included Splatter reference generation, input loading and, for scCube, VAE training. For scCube, one VAE was trained per size batch (10,000–100,000, 200,000–600,000 and 1,000,000–5,000,000 cells) and reused in memory, with the measured batch setup cost charged to every size in the setup-inclusive comparison. No model checkpoints were saved. Timing excluded imports/startup, validation, aggregation and output export. We report the mean over the three seeds, with individual seeds shown.

For memory, ALBIS and SPIDER whole-process peak resident memory served as a proxy for generation memory. scCube generation memory was the peak of resident memory sampled every 100 ms during each size's generation, with the trained VAE and reference held in memory. The setup-inclusive memory panel reports method-process peaks, including training and earlier sizes in the batch for scCube, and excludes Splatter-process memory, which was not measured. The memory panels therefore do not constitute fully matched measurements with and without setup.
